WHAT REMAINS SECURE
════════════════════════════════════════════════════════════════════════════════

✅ PRIVATE KEYS: Never touch the backend
   - Phantom SDK keeps keys in browser extension
   - Transactions signed locally by user
   - Backend never sees private keys
   
✅ NO PASSWORDS: No user authentication database
   - Stateless API
   - Rate limiting provides protection
   - Wallet address used for identification (optional)

✅ NO PERSONAL DATA: Only public blockchain data
   - Addresses are on-chain public
   - Balances visible via public RPC
   - No tracking, no analytics, no cookies

DEPLOYMENT REQUIREMENTS
════════════════════════════════════════════════════════════════════════════════

BEFORE DEPLOYING TO PRODUCTION:

☑ Create Groq API key: https://console.groq.com/keys
☑ Create Solana wallet: For FEE_ACCOUNT (where swap fees go)
☑ Create Vercel account: https://vercel.com
☑ Push code to GitHub
☑ Remove .env from git: git rm --cached .env

VERCEL DEPLOYMENT (5 STEPS):

1. Go to https://vercel.com/new
2. Import GitHub repo
3. Set Environment Variables:
   - GROQ_API_KEY (from console.groq.com)
   - FEE_ACCOUNT (your Solana wallet)
   - ALLOWED_ORIGINS_CUSTOM (your domain)
4. Deploy
5. Monitor Groq usage weekly

See DEPLOYMENT.md for detailed instructions with screenshots.

ATTACK SCENARIOS & MITIGATIONS
════════════════════════════════════════════════════════════════════════════════

SCENARIO 1: DDoS Attack (Spam /api/chat)
──────────────────────────────────────────
ATTACK: Attacker floods endpoint with requests, exhausts Groq quota
MITIGATION: Rate limit 20 messages per hour per IP
RESULT: ✅ PROTECTED - Request rejected with HTTP 429

SCENARIO 2: Cross-Site Request Forgery
────────────────────────────────────────
ATTACK: evil.com makes POST request to your /api/swap
MITIGATION: CORS whitelist only web.telegram.org
RESULT: ✅ PROTECTED - Browser blocks request (CORS error)

SCENARIO 3: API Key Leaked
──────────────────────────
ATTACK: Someone finds GROQ_API_KEY and makes unauthorized calls
MITIGATION: Store only in Vercel env vars, rotate monthly
RESULT: ✅ MANAGEABLE - Rotate key, revoke old one, no permanent damage

SCENARIO 4: Phishing / Malicious Swap
───────────────────────────────────────
ATTACK: Attacker modifies swap transaction before signing
MITIGATION: HTTPS encryption + user reviews transaction before signing
RESULT: ✅ PROTECTED - Can't modify signed transaction, user sees it

SCENARIO 5: Private Key Theft
──────────────────────────────
ATTACK: Attacker steals user's wallet private key
MITIGATION: Keys never touch backend, managed by Phantom SDK
RESULT: ✅ PROTECTED - Backend never sees keys, zero risk

SCENARIO 6: User Enumeration
─────────────────────────────
ATTACK: Attacker queries /api/traders to find all users
MITIGATION: Rate limiting + addresses are public anyway
RESULT: ✅ ACCEPTABLE - No private data revealed, rate-limited
